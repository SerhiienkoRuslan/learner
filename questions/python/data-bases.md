<details>
<summary>54. Які є базові методи роботи з SQL- базою даних у Python?</summary>

Робота будується за специфікацією **DB-API 2.0 (PEP 249)** через спеціалізовані драйвери (`psycopg2`, `asyncpg`, `sqlite3`): створюється з'єднання `connect()`, відкривається курсор `cursor()`, виконуються виклики `execute()` або `executemany()`, отримуються рядки через `fetchone()` / `fetchall()`, а зміни фіксуються методом `commit()` або скасовуються через `rollback()`. Для вищого рівня абстракції використовують **Query Builders** та **ORM** (наприклад, **SQLAlchemy**, **Django ORM**), які маплять таблиці на класи та самостійно генерують SQL-запити.
</details>

<details>
<summary>55. Що таке SQL-транзакція?</summary>

**SQL-транзакція** — це неподільна група операцій над даними, яка виконується за принципом «все або нічого»: вона або повністю успішно фіксується (**commit**), або за будь-якої помилки повністю відкочується (**rollback**), повертаючи базу до початкового стану. Транзакції гарантують дотримання властивостей **ACID**: атомарність (**Atomicity**), узгодженість (**Consistency**), ізольованість (**Isolation**) та надійність/довговічність збереження даних (**Durability**).
</details>

<details>
<summary>56. Як зробити вибірку із SQL-бази з простою агрегацією?</summary>

Для агрегації використовуються стандартні функції на кшталт **COUNT**, **SUM**, **AVG**, **MIN** або **MAX**, які за наявності неагрегованих колонок комбінуються з обов'язковим групуванням рядків через **GROUP BY** (та опціональною фільтрацією вже згрупованих значень через **HAVING**):

```sql
SELECT department_id, COUNT(*) AS total_employees, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 2000;
```
</details>

<details>
<summary>57. Який вигляд має запит, який виконує JOIN між таблицями й до самих себе?</summary>

З'єднання двох різних таблиць зазвичай виконується оператором **INNER JOIN** (або **LEFT JOIN**), а з'єднання таблиці самої з собою називається **SELF JOIN** і реалізується за допомогою обов'язкових унікальних псевдонімів (**аліасів**), щоб СУБД розрізняла рядки однієї й тієї ж сутності (наприклад, співробітника та його керівника):

```sql
-- JOIN між двома різними таблицями:
SELECT u.name, o.total_amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- SELF JOIN (з'єднання таблиці самої із собою):
SELECT e.name AS employee_name, m.name AS manager_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```
</details>

<details>
<summary>58. Як відправляти запити у SQL-базу даних без ORM?</summary>

Запити без ORM надсилаються через курсор низькорівневого драйвера (наприклад, `sqlite3`, `psycopg2` чи `asyncpg`) за допомогою методу `execute()`, де всі змінні передаються виключно окремим кортежем або списком параметрів для захисту від **SQL-ін'єкцій**:

```python
import sqlite3

with sqlite3.connect("database.db") as conn:
    cursor = conn.cursor()
    cursor.execute("SELECT id, name FROM users WHERE is_active = ?", (True,))
    active_users = cursor.fetchall()
```
</details>

<summary>84. Різниця між SQL і NoSQL?</summary>

SQL (реляційні бази даних, як-от PostgreSQL) використовує **строгу схему (schema)**, дані зберігаються у вигляді **таблиць** зі зв'язками між ними, а масштабування переважно **вертикальне**. NoSQL (нереляційні БД, як-от MongoDB чи Redis) зберігає дані у вигляді **документів, пар ключ-значення, графів або колонок**, має **динамічну схему** та легко масштабується **горизонтально**, що краще підходить для неструктурованих даних, гнучкої розробки та дуже великих навантажень без жорстких вимог до транзакцій.
</details>

<details>
<summary>85. Як оптимізувати SQL-запити?</summary>

Оптимізація починається з аналізу плану виконання запиту за допомогою команди **EXPLAIN / EXPLAIN ANALYZE**. Ключові кроки включають: створення правильних **індексів** (особливо для полів у `WHERE`, `JOIN` та `ORDER BY`), уникнення важких вибірок типу `SELECT *` на користь переліку конкретних колонок, відмову від виклику функцій на індексованих колонках у фільтрах, використання **пагінації (LIMIT/OFFSET)**, а також кешування частих результатів на рівні додатка (Redis).
</details>

<details>
<summary>86. Які є рівні ізоляції транзакцій?</summary>

Існує чотири стандартизовані рівні ізоляції, які балансують між продуктивністю та захистом від аномалій читання. Від найслабшого до найсуворішого: **Read Uncommitted** (читання незафіксованих даних іншими транзакціями — найшвидший, але з "брудним" читанням), **Read Committed** (захищає від "брудного" читання, є дефолтним у PostgreSQL), **Repeatable Read** (гарантує, що прочитані дані не зміняться до кінця транзакції) та **Serializable** (повністю ізолює транзакції так, ніби вони виконуються строго послідовно одна за одною).
</details>

<details>
<summary>87. Які є види індексів?</summary>

Найпоширеніший вид у більшості СУБД — це **B-Tree індекс (B-дерево)**, який ідеально підходить для пошуку на рівність та діапазони (`<`, `>`). Також існують **Hash-індекси** (виключно для швидкого пошуку на точну рівність), **GIN (Generalized Inverted Index)** (для повнотекстового пошуку, роботи з масивами або JSONB-документами), **GiST** (для геометричних та просторових даних), а також **часткові індекси (Partial Indexes)**, які індексують не всю таблицю, а лише рядки, що відповідають певному фільтру (наприклад, тільки активні користувачі).
</details>

<details>
<summary>88. Точкові питання з вибору БД, рушіїв БД?</summary>

Вибір залежить від структури даних: для суворої фінансової логіки або складних зв'язків обирають **PostgreSQL** чи **MySQL** (з рушієм **InnoDB** для повноцінної підтримки ACID-транзакцій). Для надшвидкого кешування та зберігання сесій підійде **Redis** (In-memory сховище). Для каталогу товарів без жорсткої схеми або прототипування беруть **MongoDB**. Для збереження логів та текстового пошуку — **Elasticsearch**, а для аналітики величезних обсягів даних (OLAP) — колонкові БД на кшталт **ClickHouse**.
</details>

<details>
<summary>89. Front-end: чи є досвід роботи із «сучасним» JS (Babel, Webpack, TS, ES)?</summary>

Сучасний фронтенд базується на стандартах **ECMAScript (ES6+)**, що додали стрілочні функції, проміси та деструктуризацію. **TypeScript (TS)** розширює JS статичною типізацією, ловлячи помилки ще до компіляції. Для збірки застосунків використовуються бандлери (класичний **Webpack** або значно швидші сучасні альтернативи на кшталт **Vite** чи **Rollup**), які мініфікують код та об'єднують модулі. **Babel** виконує роль транспілятора, перетворюючи найновіший синтаксис на сумісний зі старішими браузерами код (хоча сьогодні його часто замінюють швидшим SWC).
</details>

<details>
<summary>90. DevOps: чи працювали з Docker-контейнерами, пояснити основні терміни K8s (кластер, pod, node, deployment, service), що таке Kibana?</summary>

**Docker** ізолює додаток разом з усіма залежностями в єдиний портативний контейнер. **Kubernetes (K8s)** оркеструє ці контейнери на рівні **Кластера**. У ньому **Node** — це фізичний або віртуальний сервер, **Pod** — найменша одиниця розгортання (один або кілька контейнерів), **Deployment** — контролер, що автоматично створює та оновлює поди, а **Service** — стабільна мережева точка доступу до динамічних подів. **Kibana** — це вебдашборд зі стеку ELK, призначений для візуалізації, пошуку та аналізу величезних масивів логів (з Elasticsearch).
</details>

<details>
<summary>91. Алгоритми: що таке часова складність алгоритму (time complexity)?</summary>

**Часова складність**, яка описується математичною нотацією **Big-O (O-велике)**, визначає, як швидко зростає час виконання алгоритму залежно від збільшення кількості вхідних даних ($N$). Вона вимірює не час у секундах, а **кількість базових операцій** у найгіршому випадку. Це дозволяє абстрактно порівнювати ефективність підходів: наприклад, доступ за індексом у масиві має константну складність **$O(1)$**, лінійний пошук — **$O(N)$**, а сортування бульбашкою — квадратичну **$O(N^2)$**.
</details>

<details>
<summary>92. Поглиблені знання Linux: як зайти на зовнішній сервер, працювати з пакетами, налаштувати середовище та виконувати операції?</summary>

Доступ на сервер здійснюється через термінал за допомогою протоколу **SSH** (зазвичай з використанням RSA/Ed25519 ключів: `ssh user@ip`). Встановлення та оновлення пакетів залежить від дистрибутива: в Ubuntu/Debian використовується **APT** (`sudo apt update && sudo apt install <package>`). Налаштування середовища робиться через експорт змінних у файлах `.bashrc` або `.profile`. Виконання операцій вимагає впевненого володіння базовими утилітами (`ls`, `grep`, `chmod` для прав, `tail` для логів) та керування фоновими сервісами через **systemd** (`systemctl`).
</details>

<details>
<summary>93. Специфічно для Data Science: як працювати з пакетами для обробки та візуалізації даних (NumPy, Pandas та інші)?</summary>

Для числових обчислень використовується **NumPy**, який надає високоефективні багатовимірні масиви (`ndarray`) та швидкі математичні операції, написані на C. Для маніпуляцій з табличними даними стандартом є **Pandas** зі структурами **DataFrame** (двовимірні таблиці) та **Series** (колонки), що дозволяють групувати, фільтрувати та очищати дані. Для візуалізації застосовують базову бібліотеку **Matplotlib** або високорівневий **Seaborn** (для статистичних графіків), а для інтерактивних дашбордів — **Plotly**.
</details>
